# ChessPaa's Wonderland

A cel-shaded 3D theme park at golden-hour dusk, where a twinkly grandfather with a
lantern teaches children to play chess. There are no lessons here — only rides, warm
light, and a grandfather who has been watching the whole time and always has something
kind and true to say about the move you just made.

---

## Run it

```bash
npm install
npm run dev
```

Then open **<http://localhost:3000/park>**.

Two commands. No account, no sign-up, no API key, no database, no build step. The first
load compiles the scene, so give it a few seconds — after that you are in the valley.

**It is offline-capable once loaded.** Pull the network cable and keep playing: Stockfish
runs in a Web Worker on the device, the puzzles are bundled JSON, and every mesh, texture
and sound is generated by the game's own code at runtime. Nothing is fetched while a
child is playing.

> The older 2D pages (`/`, `/play`, `/pieces`, `/adventure/*`) still carry a sign-in flow
> backed by Postgres. `/park` needs none of it, and no route requires you to be signed in.
> See [Status](#status).

## What's free and open under the hood

| Piece | What it does | Licence |
|---|---|---|
| [chess.js](https://github.com/jhlywa/chess.js) | The rules authority. Legality, FEN, SAN, check, promotion — nothing else in this repo is allowed to decide whether a move is legal. | BSD-2 |
| [Stockfish 18](https://stockfishchess.org/) (WASM) | ChessPaa's brain. The `lite-single` build in `public/stockfish/`, driven over UCI from a Web Worker by `src/lib/chess/engine.ts`. Single-threaded, so it needs no cross-origin isolation headers and works everywhere. | **GPLv3** |
| [Lichess open puzzle database](https://database.lichess.org/#puzzles) | 1,060 curated kid-friendly puzzles in `src/lib/data/puzzles/` — 490 tactics across seven themes, 400 in five difficulty bands for the train, 170 endgames for the wheel. Pre-filtered for popularity and low rating (600–1698, median 1107), and all 1,060 replay cleanly through chess.js — re-check it any time by walking each `fen` + `moves` line through a `Chess` instance. | CC0 |

### And the point of pride: **every asset is generated by the game's own code**

No downloaded models. No downloaded textures. No downloaded audio samples. No purchased
LUT. Not one. Everything you look at is a list of numbers that turns into geometry, or a
canvas the game paints for itself at boot:

- **Meshes** — hand-authored lathe profiles and merged `BufferGeometry`. The chess pieces
  are turned on a lathe exactly the way real wooden pieces are
  (`src/three/core/geometry/pieces.ts`); ChessPaa is capsules, blobs and lathes
  (`src/three/characters/ChessPaa.tsx`); the valley is a displaced plane with the river
  carved by the same height function (`src/three/world/terrain.ts`).
- **Textures** — painted with canvas2D and cached: wood grain, snow, ice, parchment,
  bunting stripes, glow sprites, the board (`src/three/core/textures/procedural.ts`),
  plus the ride signage atlases and the clock face (`src/three/world/Landmarks.tsx`).
- **The toon ramps** — six hand-authored luminance gradients (four to six hard bands each)
  written into 32×1 `DataTexture`s with `NearestFilter` (`src/three/core/toonRamp.ts`).
- **The colour-grading LUT** — `buildWarmLUT()` computes a 16³ `Data3DTexture` in a triple
  loop at boot, in the same file. A colourist's grade, expressed as arithmetic.
- **Sound** — WebAudio oscillators and gain envelopes (`src/lib/sound.ts`). ChessPaa's
  voice is the browser's own speech synthesis.
- **Type** — a CSS stack of warm rounded faces the device already has
  (`--font-park` in `src/app/globals.css`). Deliberately *not* `next/font/google`: fetching
  a webfont at build time breaks an offline box and contradicts the rule. The reasoning is
  written down in `src/app/layout.tsx`.

**The two honest exceptions**, both outside the park: the Stockfish WASM binary (7.3 MB of
compiled chess engine — code, not art), and seven PNGs plus one SVG in `public/`, used only by
the legacy 2D pages. Nothing in `/park` touches either except the engine.

## Kid-safety

- **No accounts** at `/park`, and no route in the app requires sign-in to play.
- **No telemetry. No analytics. No tracking pixels. No third-party scripts.**
- **No chat, no multiplayer, no user-generated content, no leaderboards** — nothing a
  stranger can send a child.
- **No ads, no in-app purchases, no upsells.**
- **No data collection.** Progress — tickets, stars, best scores, the learner profile — is
  local-only in `localStorage` (`src/lib/progress.ts`, `src/lib/chess/levels.ts`). It never
  leaves the device. Clearing site data is a complete erase.
- **COPPA-minded by construction.** There is no personal information to protect because
  none is ever asked for, stored, or sent.
- **No fail states.** The tutor's own rules (written at the top of
  `src/lib/chess/tutorEngine.ts`) are *never stall, never scold, never cry wolf*. The
  harshest of the five tiers is `careful`, and the bluntest thing it can say is "That's
  expensive." (reserved for the oldest age band; little ones get "Careful…" or "Hold on…").
  The words "blunder", "mistake", "wrong" and "bad" appear nowhere in `voiceLibrary.ts`.
  There is no red X, no buzzer, no losing streak. An illegal drop springs home instead of
  erroring; a piece with no legal moves cannot be lifted at all, so a child is never shown
  an empty ring of hints.

**The one network call in the whole app**, and it is off by default: the optional
"Ask ChessPaa why 🤔" button posts *engine findings about one position* — never anything
about the child — to `/api/coach`. Without `ANTHROPIC_API_KEY` set, that route composes the
answer offline from the same facts and never leaves the machine. Leave the key unset and
the app makes no outbound requests at all.

## The screenshot harness

```bash
node harness/capture.mjs                       # all 11 shots, retina, into shots/
node harness/capture.mjs --only crest          # just the reveal
node harness/capture.mjs --url http://localhost:3000 --out shots --dpr 2 --w 1440 --h 900
```

Needs the dev server already running.

**Why it exists:** because every visual claim in this project gets checked against a real
captured frame, never against an assumption about what the code does. It was built before
the park was, deliberately. If a document here says the crest reveal stacks the valley into
flat paper cards, there is a PNG in `shots/` you can open and disagree with — and as of the
current `shots/03-crest.png`, you would be right to. See "Known wrinkles".

It drives a headless Chromium through `window.__park`, the tiny control surface installed
by `src/three/harnessBridge.ts`: `pose({rig, camera, dusk})` to place a camera
deterministically, `stats()` for draw calls and triangles, `debug()` to list what is
actually in the scene graph. Posing beats scrubbing a timeline — the same rig name always
produces the same frame. Twelve named rigs live in `RIGS`, from `gate` to `crest` to
`board`; the default run shoots eleven of them (`free` is the manual one). Results land in
`shots/`, with `shots/report.json` carrying per-shot stats and any console errors.

Two things to fix in the harness itself, both outside these docs: the header comment points
at `src/three/harness-bridge.ts`, which does not exist (it is `harnessBridge.ts`), and a run
overwrites only the shots it takes — so a partial run leaves `shots/` a mix of vintages, which
is exactly how the current set got into the state described under Status.

**One caveat, stated plainly:** the harness rasterises through SwiftShader (software GL),
so `report.json` reports `fps: 0`. It verifies *composition, colour and regressions* — what
is on screen and whether it changed. It does **not** verify framerate. The 60fps-at-retina
bar has to be measured on real hardware.

## Status

Read this before you believe anything else in this file. Every claim below was verified
against the source. Claims about what is *on screen* were checked against the PNGs in
`shots/` — with one caveat you need before you trust them:

> **The frames in `shots/` are not one coherent set.** They were captured across 38 minutes
> of a moving codebase (17:08 → 17:46), so they disagree with each other. `04-drone`,
> `06-parade`, `07-coaster`, `09-train` and `10-board` are the oldest (17:08–17:10) and show
> a valley with almost none of the fair standing in it; `02-plaza` and `11-lake` are from
> 17:22–17:25; only `01-gate`, `03-crest`, `05-chesspaa` and `08-ferris` (17:43–17:46) show
> the park as the code currently builds it. `shots/report.json` likewise holds stats for a
> single shot (`05-chesspaa`), not the whole run. **Re-run the harness before citing any
> frame as current evidence.**

### Built and running in `/park`

- **The cel pipeline.** Palette, toon ramps, the toon material with its warm fresnel rim,
  inverted-hull outlines, the Sobel interior-ink pass, banded fog, the code-generated warm
  LUT, and the full post chain in `src/three/Stage.tsx`. Working end to end: `shots/01-gate.png`
  shows warm ink, hard toon bands, the cut-paper pine wall and the painted sky, with nothing
  grey or physically based anywhere in frame. The one part not yet delivering is the banded
  fog — see "Known wrinkles".
- **The valley.** Displaced terrain with the frozen river carved into it, ice, snow banks,
  the flat plaza, trodden walkways with signposts, and a 620-tree pine wall with a flat
  cut-paper far band. (`terrain.ts`, `props.ts`, `paths.ts`)
- **The coaster spine** — rails, sleepers and supports swept along `SPINE_CURVE`, threading
  every attraction together. (`coasterSpine.ts`)
- **The sky** — painted dusk dome, two parallax layers of hard-edged cel clouds, drifting
  atmosphere motes. (`Sky.tsx`, `SkyMaterial.ts`)
- **The fair.** All of `Landmarks.tsx` — the biggest file in the repo — is mounted: piece
  parade, tactics station, Ferris wheel, puzzle train, big top, carousel, plaza dressing,
  painted signage, steam and glow particles. `shots/01-gate.png` and `shots/03-crest.png`
  show the big top, carousel, Ferris wheel and booths standing and lit.
- **Lanterns and bunting** — practical point lights pooling warmth on the snow, plus
  breathing fairy-lights on `NO_INK_LAYER`.
- **ChessPaa** is mounted from `Park.tsx` at `[6.2, terrainHeight(6.2, 60), 60]`, and the rig
  underneath him (`chessPaaRig.ts`: springs, two-bone IK, Verlet chains for the beard and
  scarf, a pendulum for the lantern) is complete and type-clean.
  ⚠️ **But he does not appear on screen.** The `chesspaa` rig is aimed straight at him
  (camera `[3.4, 1.95, 56.4]` → target `[6.1, 1.5, 60.0]`) and `shots/05-chesspaa.png` — the
  most recent frame in the set — contains coaster supports, snow, pines and one lantern, and
  **no grandfather at all**. Not "hard to read": absent. Something between the mount and the
  draw is failing, and until it is found, the character the whole game is named after is not
  in the park. This is the highest-priority bug in the project. (It also means the
  273-draw/843k-triangle figure below was measured on a frame missing the hero.)
- **The camera rigs and the harness bridge** — twelve poses, spring-damped follow,
  deterministic posing from `window.__park`.
- **Adaptive pixel ratio** — a simple FPS-driven DPR governor lives inside `Stage.tsx`.
- **The chess brain** — `engine.ts` (Stockfish over UCI in a Worker), `motifs.ts` (forks,
  pins, skewers, hanging pieces, mate-in-one, static exchange evaluation), `coach.ts`,
  `phrases.ts`, `levels.ts`, `voiceLibrary.ts` and `tutorEngine.ts` are all written and
  type-clean.

### Built, complete, and not yet wired in

These are finished modules with no import anywhere. They are the next wiring job, not the
next writing job.

- **`src/three/board/Board3D.tsx`** (~2,000 lines) — the 3D board. Drag *and* tap-to-move,
  generous invisible hit boxes, snap-to-nearest-legal, a four-piece promotion picker,
  tutor-driven square highlights, thirty-two piece characters that wake up on their turn.
  **Nothing imports it.** The `board` camera rig points at the origin and
  `shots/10-board.png` is empty fog with one distant tree in it. This is the single largest
  gap in the project.
- **`src/three/world/ParkLife.tsx`** + `parkLifeData.ts` — walking piece-folk, crows lifting
  out of the pines, glitter over the ice, breath fog, and the dusk drift. Deterministic and
  instanced. Not mounted.
- **`src/three/characters/Grandchildren.tsx`** — two small riders built from ChessPaa's
  plush vocabulary, with reactions (`idle`, `lean`, `clap`, `gasp`). Not mounted.
- **`src/three/characters/PieceCharacters.tsx`** — piece faces, personality idles, cheers
  and comic slumps. Reachable only through `Board3D`, so currently unreachable.
- **`src/three/world/Gate.tsx`** + `gateGeometry.ts` (~2,200 lines of baked geometry) — the
  painted gates, the arrival. Not mounted.
- **`src/three/world/RideController.tsx`** + `CoasterCar.tsx` — the on-rails ride between
  hubs, with the authored slow-climb / crest-stall / drop choreography. Not mounted.
- **`src/three/cameras/{cinematic,freeLook,slowmo}.ts`** — real lens maths, free-look
  controls, and a slow-motion swell for brilliancies. `Stage.tsx` uses its own simpler rig
  controller instead; none of these three are imported.
- **`src/three/core/{perf,lod}.ts`** — a four-rung quality ladder (`low`/`medium`/`high`/`ultra`,
  `celPipeline: true` at every rung) with a `PerfGovernor`, plus a hysteresis LOD system.
  `perf.ts` is read only by the unmounted `ParkLife`; `lod.ts` is read only by `perf.ts`
  (for `setGlobalLodBias`). Neither reaches a rendered frame.
- **`src/three/ui/`** — `StorybookUI.tsx`, `SpeechCard.tsx`, `Hud.tsx`, `parkMapFoldout.tsx`,
  built on `src/lib/a11y.ts`. The in-park HUD, speech cards, park-map foldout and
  accessibility surface are written; only `StorybookUI` has importers, and those are its own
  siblings. `ParkClient.tsx` still renders `Stage` alone, so `/park` remains a world you look
  at, not one you operate.
- **`src/lib/audio/`** — `synth.ts`, `soundscape.ts`, `score.ts`, `chessPaaVoice.ts` and
  `index.ts`: the synthesised spatial audio, adaptive score and ChessPaa's voice, ~4,000 lines
  of it. Nothing outside the folder imports `audio/index.ts`, so what actually plays today is
  still `src/lib/sound.ts` — eight WebAudio blips and browser TTS.
- **`src/lib/chess/tutorEngine.ts`** — the Living Tutor: tier, one selected lesson, voiced
  in this child's language, plus a hint ladder and a takeback. Complete, and **not called by
  any UI**. The 2D pages use the older, shallower `coach.ts` path instead.

> This list moves fast — several of these landed while this file was being written. Before
> trusting any "not wired in" line, re-check it: `grep -rn "from .*<module>" src`.

### Not started

- **`src/three/attractions/`** — exists, empty. The five rides are still scenery, not places
  you can play.
- **Any route that puts a child in front of the 3D board.** `/park` is scenery; the 3D game
  loop is not connected, and the hero is not currently drawing (see above).

### Known wrinkles

- Draw calls at the last recorded harness sample: **273 draws / 843k triangles / 47 programs**
  (`shots/report.json`, from the `05-chesspaa` pose only). Higher than the budget this project
  set itself. Merging and instancing are in place but not finished.
- Shadows read as large, hard, near-black shapes across the snow in both `shots/01-gate.png`
  and `shots/05-chesspaa.png` — under-shaped and far too dark for a plush storybook park.
  Lavender bounce is in the material; it is not winning against a 1.25-intensity key.
- **The valley wall is broken geometry, not a seam.** In `shots/03-crest.png` the terrain
  rears into two near-vertical cliff faces on the left and right of frame, with a hard
  straight edge and pines half-buried in them. It reads as a modelling failure, and it is the
  first thing the eye lands on in the shot the whole game is built around.
- **The crest reveal does not yet read as a painted matte.** `docs/ART_DIRECTION.md` §5 claims
  the crest stacks the valley into flat paper cards receding into honey haze. It does not:
  `shots/03-crest.png` shows the near valley and the two cliff walls, with no far bends of the
  river, no distant attractions, and the banded fog barely registering. The mechanism
  (`patchMaterialForBandedFog`, 5 bands, `Fog(fogNear, 96, 340)`) is correct in code and
  visible on the far hills in `shots/01-gate.png` — the `crest` rig simply is not framing a
  distance where it can do its job. Treat the §5 claim as the intent, not the current frame.
- `src/lib/data/pieces.ts` still points at `/music/*.mp3` files that are not in `public/`.
  Broken links on the legacy piece pages; harmless everywhere else.
- **`Atmosphere` in `src/three/world/Sky.tsx` calls `Math.random()` at build time** (eight
  calls, seeding 700 motes) instead of `rng(seed)`. It is mounted, so the drifting motes
  reshuffle on every run — exactly the thing that makes a harness regression indistinguishable
  from a coin flip. It is the only build-time `Math.random()` anywhere under `src/three/`. The
  remaining uses in the tree are runtime variety, not geometry: `phrases.ts` picking a line,
  `engine.ts` weighting a move, the legacy 2D pages shuffling a puzzle deck, and `Confetti.tsx`.
- The normal+depth prepass linearises depth against `uFar = 400` while the camera's far
  plane is 600 (`Stage.tsx`, `effects.ts`). Benign — interior ink already fades out at 0.80
  of that range — but the two numbers should agree.

### The legacy 2D game (still here, still works)

Before the park there was a complete, playable 2D version, and it has not been removed:
`/` (animated SVG park map), `/play` (a real game against ChessPaa with per-move coaching),
`/pieces` (piece rhymes and move trainers), and `/adventure/{tactics,puzzles,endgames,openings}`
(the four ride games). These use `react-chessboard`, the PNGs in `public/`, and a
better-auth + Prisma/Postgres sign-in that the park does not use and does not need. They are
the reference for what the 3D park has to beat.

`npx tsc --noEmit` passes clean across the whole repo.
